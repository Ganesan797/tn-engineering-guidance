# M2 One-Journey Question-to-Domain Map V1

**Prepared:** 2026-10-03 for the [bounded authorization](m2_one_journey_authorization_decision_2026-10-03.md). **Scope:** one first-year TNEA academic journey. This is an implementation mapping for review, not a new admission rule or content approval.

| Student step and guidance | Response class | Minimum input / trusted field | Skip, unknown and next action |
| --- | --- | --- | --- |
| “What is engineering, and what might an engineer do?” — approved M1 `AW-01`; reviewed A01 `Q026`/`Q028` | Approved orientation plus clearly labelled reviewed Tamil draft | None | Explain applied study/work before admission. Offer “What would I study?”, “How are fields different?” or the TNEA route. Marks and a branch decision are unnecessary. |
| “What would I study?” — reviewed A01 `Q035` and A04 `Q037`–`Q044` | Optional, grouped branch-subject and practical-work examples | None | Open only a field of interest; compare subjects/labs/projects and inspect the exact institution/regulation syllabus. No personal suitability or job result. |
| “How are these fields different?” — reviewed A04 `Q036`, A06 `Q047`, optional A05 `Q049` computing comparison | Content that contrasts field focus and activities, without ranking | None | Explore another field or move to the TNEA route. No branch selection, aptitude verdict or cutoff inference. |
| “How do I enter?” — approved M1 `AW-03`/`AW-05`; reviewed B01/B04 for additional route/process context | Dated, source-linked content | None | Explain that 2026 first-year TNEA covers specified seats and is one route. Offer preparation or a personal check; a diploma belongs to the separate B03/TNLEA path. |
| “What should I prepare?” — reviewed B05, subject to its evidence limits | Dated content and next action | No personal marks or documents collected | Show a private preparation checklist and official TNEA/TFC direction. Do not claim 2027 dates or upload personal documents. |
| “Which admission year?” | Route guard, then content or UNKNOWN | Intended year; engine's `ADMISSION_YEAR = 2026` | For another or unknown year, stop before personal calculation; show the applicable official-year source action. Never silently treat 2026 rules as 2027 rules. |
| “Is your Class 12 route the general academic route?” | Route guard | `StudentProfile.qualifying_stream = HSC_ACADEMIC` only when affirmed | Unknown/other stops this narrow calculation and points to the appropriate official route. Never infer HSC academic from marks. |
| “Were improved examination marks used?” | Domain input | `StudentProfile.improvement_marks_used`; ELG032 and effective marks used by ELG009 | “I don't know” maps to `null`, producing no cutoff. If false, skip improvement year/original marks. |
| “In which year were the improved marks obtained?” — only if yes | Domain input | `StudentProfile.improvement_marks_year`; ELG032 | Unknown remains `null` and stops the calculation. For 2006 onward, ask original marks; earlier years use the normal mark fields under the existing rule. |
| “What are your Mathematics, Physics and Chemistry marks?” | Existing deterministic calculation when supported | `maths_mark`, `physics_mark`, `chemistry_mark`, or `original_*` marks for disallowed post-2005 improvements; ELG009/ELG032. One subject at a time, only on a stated 100-mark scale. | Retain supplied subjects. Unknown maps to `null` and leads to a missing-information action; never substitute zero. |
| “What does the result mean?” — B08 and frozen Input/Output hierarchy | Existing deterministic `GuidanceResult.eligibility.cutoff`, `outcome`, `blocking_missing_fields` and source checks, or UNKNOWN/NEEDS_REVIEW | No extra input just to show a supported cutoff. Invoke the existing guidance service with unasked profile fields `null`; no new formula. | Show a cutoff only when ELG009 supplies it; present overall eligibility separately. If cutoff is null or eligibility needs review, explain the missing reason and next action. Do not turn a score into rank, seat or probability. |
| Informed student's direct entry | Same route guards and domain inputs | No awareness completion flag | Enter the personal path immediately; previously supplied answers remain in the progressive request state. Stage 1 exploration never becomes a prerequisite. |

**Source/review control:** The M1 awareness pack and approved Tamil copy are frozen/approved. A01–A07 V2 and B01–B08 have owner content-direction/answer acceptance but not final factual release, volunteer Tamil equivalence or real-student validation. B01/B04/B05 are available as clearly marked reviewed drafts with their 2026 scope. [B01–B08 evidence](../content/admission/student_pov_admission_evidence_int05_int08_v1.md) and `SRC002` govern the dated facts. The existing `StudentProfile`, `blankReferenceRequest`, `createGuidance`, ELG009 and ELG032 are reused. The unresolved G05 question about cutoff/eligibility coupling is not solved by inventing a standalone calculator: a non-null engine cutoff may coexist with overall `NEEDS_REVIEW`, and the UI must explain both.

**State boundary:** This local journey retains only the entered year, academic-route response, improvement response/year and up to three marks in a bounded form state. No name, contact detail, certificate or profile is stored by this path. Input is validated on every step. This is a single guided flow, not a general chat interface.
